## 2. 「中华人民共和国宪法」三份到底谁是谁

用户报告的「显示错乱」直接原因在渲染层（UI 工程师负责），但**数据侧同时存在一个语义陷阱**：三份 143/138 条的宪法，名字和内容并不对应直觉。

```
                    条数  有toc  标题有label  有序言  条号  实际是哪一版
7ffbd0c9…           143    否       否          ✅14块  裸「一」  2018修正版
5a483004b           143    是       是          ❌       第一X条  2018修正版
9eb80037            138    是       是          ❌       第一X条  1982原版
```

### 2.1 逐条 diff 结果

| 对比 | article 数 | 正文不一致条数 |
|---|---:|---:|
| `7ffbd0c9…` vs `5a483004b` | 143 vs 143 | **0** |

⇒ 这两份是**同一部法律（2018 年修正文本）的两次不同整理**，不是两个版本。

### 2.2 版本标记词实测

| 特征词 | `7ffbd0c9…` | `5a483004b` | `9eb80037`（1982） |
|---|:--:|:--:|:--:|
| 监察委员会（2018 新增） | ✅ | ✅ | ❌ |
| 国营经济（1982 原文） | ❌ | ❌ | ✅ |

第七条正文：
- `7ffbd0c9…` / `5a483004b`：**国有经济**，即社会主义全民所有制经济…
- `9eb80037`：**国营经济**是社会主义全民所有制经济…

⇒ `9eb80037` 才是真正的 1982 原文，另两份是 2018 修正版。

### 2.3 ⚠️ 决定性差异：只有 `7ffbd0c9…` 有序言

`7ffbd0c9…` 有 **14 个 `text` 块**，内容是完整的宪法序言（「中国是世界上历史最悠久的国家之一……」，共 13 段 + `## 序言` 标题）。

`5a483004b` 的 blocks 直接从 `第一章 总纲` 开始，**没有序言内容**；它的 `meta.subtitle` 仅 30 字且**在句中截断**（`（1982年12月4日第五届全国人民代表大会第五次会议通过 1982年12月4日全国人民代表大会公告公布施行`，无结尾括号）。

**因此：删除 `7ffbd0c9…` 会让 App 丢失宪法序言。这是不可接受的。**

## 3. 处置方案（方案 D：改名，不删）

| bbbs | 改前 | 改后 | 理由 |
|---|---|---|---|
| `7ffbd0c9…` | 中华人民共和国宪法 | 中华人民共和国宪法（含序言·早期整理版） | 排到组内最后；名字如实说明它有序言、结构是早期整理 |
| `5a483004b` | 宪法（2018年修正文本） | 不变 | 结构最干净，作为「点宪法」后的默认正文 |
| `9eb80037` | 宪法（1982年） | 不变 | 真正的 1982 原文，有独立价值 |

改后排序（实测）：

1. 宪法修正案（1988年） … 5. 宪法修正案（2018年）
6. 宪法（1982年）
7. 宪法（2018年修正文本）
8. 宪法（含序言·早期整理版）

**没有删除任何文件，没有改任何正文。**

### 3.1 为什么不用方案 A（删除）
删掉 `7ffbd0c9…` = 丢失宪法序言（14 个 text 块、约 1,700 字），且 `5a483004b` 无法补上。

### 3.2 为什么不用方案 B（只改名不评估）
方案 B 的思路正确，但如果只是「把它排后面」，用户点到的 `5a483004b` 是没有序言的残缺版本。所以 B 必须配合 **改名如实标注**「含序言」，这才是方案 D。

### 3.3 为什么不用方案 C（修复结构）
`label` 填充、`##` 剥离、toc 生成对 `7ffbd0c9…` 完全可行（12 个标题块的文字都在 `text` 里），但：
- UI 侧正在做 `label.ifBlank { text }` 回退（影响 325 部），修复后 `7ffbd0c9…` 就能正常显示
- 重新打包 assets 需要重新走 `bundle_laws.py` 流程
- **收益低、与他人改动重叠**

若后续仍需要彻底修复，脚本已留好位置（`tools/clean_laws.py` 的类 1）。

### 3.4 必须同步：`IMPORT_VERSION` 3 → 4
改名后若不升版本，老用户 `BundledData.isImported()` 返回 true 会直接跳过重导入，**看到的仍是旧名字**。

## 4. 宪法修正案（2018年）的结构问题

`2c909fdd678bf17901678bf59da8002d`，26 条修正案，`noNum` 序列为：

```
32, 33, …, 51, 52, 123, 124, 125, 126, 127
                ^^^^ 应为 53..57
```

**成因**：修正案第 52 条的原文是「宪法第三章『国家机构』中增加一节，作为第七节『监察委员会』；增加五条，分别作为第一百二十三条至第一百二十七条」。其后 5 块是新增的宪法条文原文，采集时误用了**宪法条号**（123–127）而不是**修正案条号**（53–57）。

**影响**：在修正案列表里看到条号从「第五十二条」直接跳到「第一百二十三条」，用户会以为缺了 70 条。
**处置**：报告，不自动改（改条号属于语义判断，需人工对照官方文本确认）。

另一个问题：该修正案的 2 个 `section` 块中，`s2` 是**说明性文字**（「第七节相应改为第八节，第一百二十三条至第一百三十八条相应改为第一百二十八条至第一百四十三条。」）却被标成 `section` 标题。
